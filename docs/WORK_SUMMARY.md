## 一、任务范围与方式

- **范围**：核心 crate `mine-mail`（`src/`）＋ 桌面壳 `mine-mail-desktop`（`web/src-tauri/`）＋ React 前端（`web/src/`）。
- **方式**：只读静态审查（8 个并行子审查 + 关键点人工复核），随后按 P0-P3 分级修复。
- **总体结论**：架构防御扎实（CAS 事务、代际防重放、UIDVALIDITY 校验、ammonia 消毒、keyring 凭据、日志白名单、minisign 签名），**未发现可远程直接利用的任意代码执行漏洞**；存在 2 个高危安全缺陷、3 个高危可靠性缺陷、1 个凭据治理缺陷及多个中低危问题。

## 四、验收与后续调整

1. **存储位置展示**：按产品要求恢复设置页完整数据目录路径展示（`data_path` 重新序列化），保留"目录选择器不预选默认路径"。
2. **链接插入问题排查**（用户报告"点添加没反应"）：
   - 根因一（本次引入的回归）：输入不带协议的裸域名（如 `www.example.com`）被 `new URL` 解析到应用自身地址；修复为自动补 `https://` 前缀。
   - 根因二（原本存在）：未选中正文文字时 `setLink` 静默失败且弹窗直接关闭；修复为保留弹窗并提示"请先在正文中选中要添加链接的文字"。
3. **验收环境问题**：用户误用了安装版旧实例（`D:\testMail\1`，1.0.4，与单实例插件冲突导致开发版被顶掉）；正确验收需关闭旧实例后运行 `npm run tauri:dev`，并核对进程路径为 `target\debug\mine-mail-desktop.exe`。
